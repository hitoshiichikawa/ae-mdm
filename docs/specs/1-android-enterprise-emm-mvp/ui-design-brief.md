## 1. プロダクト概要

- **何か**: Android Enterprise（Android Management API, 以下 AMAPI）を使った **マルチテナント型 EMM/MDM SaaS** の管理コンソール。
- **誰が使うか**: 顧客企業（テナント）の **IT 管理者**。1 日に複数回開き、端末の現況確認・トラブル対応・ポリシー調整を行う。
- **中核体験**: 「Android 業務端末を QR でエンロール → ポリシー配信 → 状態を監視 → リモートで LOCK/WIPE/REBOOT」を Web から完結。
- **トーン**: 業務系 B2B SaaS。**信頼感・可読性・操作の確実性**が最優先。装飾より情報密度。誤操作（特に WIPE）を防ぐ設計。
- **類似プロダクト（密度・パターンの参照）**: Microsoft Intune / Jamf / Hexnode / SOTI MobiControl / Scalefusion / Esper。これらの「データ密な admin console」の流儀に寄せる。

## 2. ビジュアル方向性（既定）

| 項目 | 既定 |
|---|---|
| アクセントカラー | **インディゴ系**（primary）。ステータス色は意味色（緑=準拠/成功, 赤=非準拠/失敗/危険, 琥珀=警告/同期遅延, 灰=中立/未確認） |
| テーマ | **ライト & ダーク 両対応**（すべての色は両モードで可読に） |
| 密度 | **データ密な admin 密度**（コンパクトな行高・テーブル中心・13–14px 基調） |
| 言語 | **日本語 UI**。ただし AMAPI / Managed Google Play / Fully Managed / Dedicated 等の標準用語は英日併記可 |
| 角丸・境界 | 中庸の角丸（8–12px）、**細い境界線（0.5–1px）** ベース。影は最小限（機能的なフォーカスリング程度） |
| アイコン | アウトラインアイコン（lucide 等、shadcn 標準）。意味の明確なものだけ |
| トーン&マナー | フラット・クリーン。グラデーション/光彩/過度な影は使わない |

> 変えたい点（ブランド色・ダーク優先・もっと余白多め等）があれば、この §2 を上書きして渡せば全画面に反映される。

## 3. ターゲット実装スタック（出力の語彙）

- **React + TypeScript + Vite（SPA）** / **Tailwind CSS** / **shadcn/ui**
- 状態取得 **TanStack Query** / フォーム **React Hook Form + Zod** / ルーティング **React Router** / 認証 **oidc-client-ts (PKCE)**
- デザイン成果物は以下の shadcn/ui コンポーネントにマップできる形が望ましい:
  - レイアウト: `Sidebar` / app shell, `Card`, `Separator`, `Tabs`, `Sheet`(右ドロワー), `Breadcrumb`
  - データ: `Table`/DataTable, `Badge`, `Pagination`, `Skeleton`(ローディング), `Empty state`
  - 入力: `Form`, `Input`, `Select`, `Switch`, `Checkbox`, `RadioGroup`, `Combobox`
  - アクション/フィードバック: `Button`, `DropdownMenu`(行アクション), `Dialog`/`AlertDialog`(確認), `Sonner`(トースト), `Tooltip`
  - 認可: 独自 `RoleGate`（§4）, 独自 `ConfirmDialog`（§4）

## 4. グローバル UX パターン（全画面共通）

### 4.1 アプリシェル
- **左サイドバー**（固定ナビ）+ **トップバー**（ページタイトル + テナント文脈 + ユーザー/ロール）。
- **2 つのコンソールで別シェル**（デザイン言語は共有）:
  - **tenant-console**（顧客向け / TenantAdmin・Operator・Viewer）ナビ: `ダッシュボード` / `デバイス` / `ポリシー` / `エンロール` / `アプリ` / `監査ログ` / `管理者`（自テナント固定・テナント切替なし）
  - **admin-console**（運用向け / SuperAdmin）ナビ: `テナント` / `横断ダッシュボード` / `未割当` / `横断監査ログ`
- トップバー右: 現在ユーザー名 + ロールバッジ。tenant-console は自テナント固定、admin-console は横断前提（テナント切替不要）。

### 4.2 ロールゲート（`RoleGate`）の挙動 — Req 2 / 9.2
- **権限のない操作ボタンは「非活性（disabled）+ ツールチップで理由」** を基本にする（ユーザーが機能の存在を学べる）。例: Operator に WIPE ボタンは見えるが disabled、ツールチップ「WIPE は TenantAdmin 権限が必要です」。
- **ロールがアクセスできないナビ/画面ごと**は **非表示**にする。例: `監査ログ`/`管理者` は Viewer/Operator に非表示、`テナント` は SuperAdmin のみ表示。
- 直リンク（URL 直叩き）で到達した場合は **403 画面**（§4.6）。

### 4.3 テナント文脈
- 一般ロールは常に**自テナント固定**。他テナントのデータは UI 上に一切出さない（存在も示さない）。
- SuperAdmin のみテナント横断。現在のテナント文脈を常時可視化（トップバーに表示）。

### 4.4 非同期コマンドのフィードバック — Req 6.6 / 6.7
- コマンド発行は**即時には完了しない**。発行 → トースト「LOCK を送信しました（実行待ち）」→ 端末/コマンド行のステータスチップが `実行待ち` → 通知受信で `成功`/`失敗` に更新。
- 端末詳細にコマンド履歴（種別・発行者・発行時刻・状態・完了時刻）を時系列表示。

### 4.5 確認パターン（`ConfirmDialog`）— Req 6.3 / NFR 4.1
- **不可逆操作（WIPE / テナント削除）は二段階確認**。`AlertDialog` で対象端末名を明示し、**端末名の入力 or 二度目の明示確認**を要求してから実行。危険色（赤）で表現。

### 4.6 状態の網羅（各画面で必ず用意）
空 (Empty) / ローディング (Skeleton) / エラー (再試行) / **権限拒否 (403)** / 部分エラー。ドメイン固有状態は各画面の「状態」欄を参照。

### 4.7 共通ステータス語彙（色とラベルを固定）
| 種類 | 値とラベル | 色 |
|---|---|---|
| コンプライアンス | `準拠` / `非準拠` / `未確認` / `サポート対象外` | 緑 / 赤 / 灰 / 灰(淡) |
| 同期状態（独立指標） | `同期遅延`（最終同期 > 24h） | 琥珀 |
| 管理モード | `Fully Managed` / `Dedicated (Kiosk)` | 青 / 紫 |
| コマンド状態 | `実行待ち` / `成功` / `失敗` / `タイムアウト` | 灰(淡) / 緑 / 赤 / 琥珀 |
| テナント状態 | `バインド未完了` / `有効` / `無効` | 琥珀 / 緑 / 灰 |

> **注**: 「コンプライアンス」と「同期遅延」は**直交する別指標**。準拠かつ同期遅延、もありうる（バッジを2つ併記）。

## 5. RBAC 可視性マトリクス（誰が何をできるか）

| 操作 / 画面 | Viewer | Operator | TenantAdmin | SuperAdmin |
|---|:---:|:---:|:---:|:---:|
| 端末・ポリシー・アプリの**閲覧** | ✓ | ✓ | ✓ | ✓ |
| LOCK / REBOOT 発行 | ✗ | ✓ | ✓ | ✓ |
| **WIPE** 発行（二段階確認） | ✗ | ✗ | ✓ | ✓ |
| エンロール（トークン発行/QR） | ✗ | ✓ | ✓ | ✓ |
| ポリシー作成・編集・割当 | ✗ | ✗ | ✓ | ✓ |
| アプリ承認（Managed Play）・割当 | ✗ | ✗ | ✓ | ✓ |
| 監査ログ閲覧 | ✗ | ✗ | ✓ | ✓（全テナント） |
| 管理者の追加・ロール変更 | ✗ | ✗ | ✓（自テナント） | ✓（全テナント） |
| テナント作成・削除・横断ビュー | ✗ | ✗ | ✗ | ✓ |

> 監査ログ閲覧は **TenantAdmin 以上**（確定済み既定）。Operator はエンロール可（requirements 3 の actor 定義に準拠）。

## 7. 画面別仕様

各ブロックを 1 画面ずつ Claude Design に渡す。書式: **目的 / 主要データ / 主要アクション / ロール可視性 / 状態 / 構成要素 / 制約**。

### 7.1 ログイン / コールバック（`auth`）— Req 2 / NFR 5
- **目的**: OIDC でログイン。SaaS の第一印象。
- **主要データ**: プロダクト名・ロゴ、「OIDC でログイン」ボタンのみ（ID/PW 自前管理はしない）。
- **アクション**: ログイン開始（IdP へリダイレクト）、ログアウト後の再ログイン。
- **状態**: 既定（ログイン前）/ 認証中 / **認証失敗（エラーメッセージ）** / セッション失効後の再ログイン誘導。
- **構成**: 中央寄せのミニマルなカード。ブランドを軽く。`CallbackPage` は処理中スピナーのみ。
- **制約**: 認証失敗時はセッションを発行しない旨が伝わるメッセージ。

### 7.2 アプリシェル（共通）— Req 9
- **目的**: 全画面の骨格。ナビゲーションとテナント文脈・ロール表示。
- **主要データ**: §4.1 のナビ項目、現在テナント名、現在ユーザー（email + ロールバッジ）。
- **アクション**: ナビ遷移、SuperAdmin のテナント切替、ユーザーメニュー（ログアウト）。
- **ロール可視性**: §4.2（ナビの出し分け）。
- **状態**: ナビの選択中ハイライト、折りたたみ（任意）。
- **構成**: 左 `Sidebar` + トップバー。レスポンシブで狭幅時はサイドバー折りたたみ。

### 7.3 デバイス一覧（`devices`）— Req 5
- **目的**: 自テナント端末の現況を俯瞰し、対処すべき端末（非準拠/同期遅延）を素早く発見。
- **主要データ（テーブル列）**: 端末名/モデル（`hardware_info`）・**モード**バッジ・適用ポリシー名・**コンプライアンス**バッジ（+ `同期遅延`）・最終同期（`last_status_at` の相対表示）・行アクション。
- **上部**: 概況メトリクス（総端末/準拠/非準拠/同期遅延）、**コンプライアンスフィルタ**、モードフィルタ（すべて/Fully Managed/Dedicated）、検索。
- **アクション**: 行クリックで詳細、行から直接 LOCK/REBOOT/WIPE（権限ゲート）、エンロールへの導線。
- **ロール可視性**: 全ロール閲覧。コマンドボタンは §5 に従いゲート。
- **状態**: 空（端末0台 → 「最初の端末をエンロール」CTA）/ ローディング / エラー / 非準拠強調 / 同期遅延強調 / **未割当端末の注意表示**（運用者向け、テナント特定不能のケース）。
- **構成**: メトリクスカード + DataTable（`table-layout: fixed`、行アクションは `DropdownMenu` も可）。
- **制約**: 他テナント端末は一切表示しない。Android 10 未満は `サポート対象外`。

### 7.4 デバイス詳細（`devices` + `commands`）— Req 5.2/5.3/7.5 / Req 6
- **目的**: 1 端末の全情報とリモート操作の起点。
- **主要データ**: 管理モード、適用中ポリシー（リンク）、**コンプライアンス状態 + 非準拠理由**（`non_compliance_details` を人間可読に）、ハードウェア情報（シリアル/IMEI/MEID/MAC 等）、ソフトウェア情報（OS/ビルド）、最終同期、エンロール日時、**インストール済み管理対象アプリ**（パッケージ名 + バージョン）、**コマンド履歴**（時系列）。
- **アクション**: LOCK / REBOOT / **WIPE（二段階確認）** / ポリシー再割当。
- **ロール可視性**: §5。WIPE は TenantAdmin+、LOCK/REBOOT は Operator+。
- **状態**: ローディング / エラー / 非準拠（理由カード強調）/ 同期遅延バナー / **コマンド発行中（実行待ちチップ）** / コマンド成功・失敗の反映 / 403。
- **構成**: ヘッダ（端末名 + バッジ群 + アクションボタン）→ タブ or セクション（概要 / アプリ / コマンド履歴）。右 `Sheet` で詳細を出す案も可。
- **制約**: コマンドは非同期（§4.4）。WIPE は §4.5 の二段階確認必須。

### 7.5 エンロール（`enrollment`）— Req 3
- **目的**: 新規端末を QR で登録するためのトークン発行と QR 提示。
- **主要データ**: モード選択（**Fully Managed / Dedicated(Kiosk)**）、Dedicated 時は適用する Kiosk ポリシー選択、有効期限、発行済みトークン一覧（モード/有効期限/発行者）。
- **アクション**: トークン発行 → **QR コード表示**（大きく、印刷/ダウンロード可）、手順ガイド（端末初期化→QR スキャン）、トークン失効。
- **ロール可視性**: Operator+。
- **状態**: 既定（発行前フォーム）/ 発行直後（QR 表示）/ **トークン期限切れ・使用済み**の表示 / エラー。
- **構成**: 左にフォーム、右に QR プレビュー。発行後は QR を主役に、設定手順を併記。
- **制約**: QR の中身は AMAPI トークン由来。**zero-touch/NFC は対象外**（このMVPでは QR のみ）。

### 7.6 ポリシー一覧（`policies`）— Req 4
- **目的**: テナントのポリシーを管理し、端末への適用状況を把握。
- **主要データ**: ポリシー名・バージョン・適用端末数・最終更新（者/時刻）。
- **アクション**: 新規作成、編集、複製（任意）、端末への割当。
- **ロール可視性**: 閲覧は全ロール、作成/編集/割当は TenantAdmin+（Operator は読み取りのみ）。
- **状態**: 空 / 一覧 / エラー / 403（編集ボタンのゲート）。
- **構成**: DataTable。行から編集へ。

### 7.7 ポリシー編集（`policies`、5 領域タブ）— Req 4.2
- **目的**: 1 ポリシーを **5 領域**で編集。複雑な構造化フォーム。
- **タブ（5 領域）**:
  1. **アプリ管理** — 承認済みアプリの追加、インストール種別（`FORCE_INSTALLED` / `AVAILABLE` / `BLOCKED` / `KIOSK`）、権限既定。**上限 3,000 件**を超えると保存不可。
  2. **パスワード** — 品質/最小桁数/履歴/有効期限/失敗時挙動。
  3. **セキュリティ** — 暗号化、提供元不明アプリ、Play Protect、開発者設定、工場出荷リセット禁止 等。
  4. **システム更新** — `AUTOMATIC` / `WINDOWED`(時間帯) / `POSTPONE` / `KEEP_CURRENT`、凍結期間。
  5. **Kiosk** — 単一/複数アプリ Kiosk、ステータスバー/ナビ/電源ボタン制御（Dedicated 向け）。
- **アクション**: 保存（upsert）、バリデーション、割当端末への配信プレビュー。
- **ロール可視性**: TenantAdmin+。
- **状態**: 編集中 / **バリデーションエラー（不正値・上限超過を項目単位で表示）** / 保存中 / 保存成功 / 競合（バージョン）/ 403。
- **構成**: 上部に共通ヘッダ（名前/保存）、`Tabs` で 5 領域。フォームは RHF + Zod 前提。Kiosk タブは Dedicated 端末に効く旨の補足。
- **制約**: 入力詳細は AMAPI の Policy フィールドに対応（ae-api-feature.md §5 参照）。実装語彙ではなく「管理者が理解できるラベル」で。

### 7.8 アプリ配信（`apps`）— Req 7
- **目的**: Managed Google Play でアプリを承認し、ポリシー経由で端末へ配信。
- **主要データ**: 承認済みアプリカタログ（アイコン/名称/パッケージ名/承認日時）、各アプリのポリシー割当（強制/任意）。
- **アクション**: **Managed Google Play iframe を開いてアプリ承認** → カタログに反映、ポリシーへ `FORCE_INSTALLED`/`AVAILABLE` 割当、各端末のインストール状況参照。
- **ロール可視性**: TenantAdmin+。
- **状態**: 空（未承認）/ カタログ表示 / iframe 表示中 / 同期中 / エラー。
- **構成**: カタログ（カードグリッド or テーブル）+ 「アプリを追加」で **iframe をモーダル/パネル表示**。
- **制約（重要）**: **Managed Google Play の iframe 内部は Google 提供であり再デザインしない**。コンソール側がデザインするのは「カタログ」「割当 UI」「iframe を埋め込む枠」。

### 7.9 監査ログ（`audit`）— Req 9.4/9.5 / NFR 4
- **目的**: 重要操作の追跡。コンプライアンス対応。
- **主要データ**: 発生時刻・実行者・操作種別（WIPE/ロール変更/ポリシー変更 等）・対象リソース・結果（成功/失敗）・詳細。
- **アクション**: 時系列表示、**絞り込み（操作種別/実行者/対象/期間）**、詳細展開。SuperAdmin は**全テナント横断**＋テナント列。
- **ロール可視性**: TenantAdmin+（Viewer/Operator 非表示）。
- **状態**: 空 / 一覧 / フィルタ結果0件 / エラー。
- **構成**: フィルタバー + タイムライン/テーブル。**追記専用（編集不可）**であることが伝わる読み取り専用トーン。

### 7.10 管理者 & ロール管理（`admins`）— Req 2.3/2.9
- **目的**: テナント内の管理者一覧とロール割当の管理。
- **主要データ**: 管理者（email/OIDC subject）・割当ロール・追加日。
- **アクション**: 管理者の追加・削除、**ロール変更（監査記録される）**。
- **ロール可視性**: TenantAdmin+（自テナント）、SuperAdmin（全テナント）。
- **状態**: 一覧 / 追加フォーム / **ロール変更の確認** / 403。
- **構成**: DataTable + ロール `Select`/`Badge`。ロール変更は確認 + 監査記録の明示。

### 7.11 テナント管理（`tenants`、**admin-console**、SuperAdmin）— Req 1
- **目的**: 顧客テナントの作成と Android Enterprise バインド状態の管理。
- **主要データ**: テナント名・**状態（バインド未完了/有効/無効）**・enterprise 名・作成日・端末数。
- **アクション**: **テナント作成**（SuperAdmin 代行で Enterprise 作成/バインド）、状態確認、無効化（二段階確認）。
- **ロール可視性**: SuperAdmin のみ。
- **状態**: 一覧 / 作成ウィザード / **バインド処理中** / **バインド失敗（操作不可の警告）** / 無効化確認。
- **構成**: テナント一覧テーブル + 作成フロー（Enterprise バインドのステップ可視化）。バインド未完了のテナントは端末/ポリシー操作不可である旨を明示。

### 7.12 ダッシュボード（共通、任意）— Req 5 派生
- **目的**: ログイン直後の概況。非準拠/同期遅延/最近のコマンド/エンロール状況のサマリ。
- **主要データ**: 端末コンプライアンス内訳、要対応端末、最近のアクティビティ。
- **アクション**: 各サマリから該当一覧へドリルダウン。
- **構成**: メトリクスカード + 小さなリスト/チャート。データ密だが圧迫しない。

### 7.13 admin-console 専用画面（横断系）

tenant-console には無い、SaaS 運用者（SuperAdmin）向け画面。詳細プロンプトは [ui-design-prompts.md](ui-design-prompts.md) の admin-console 節 A〜D。

- **横断ダッシュボード**（`/`）: 全テナント横断の運用概況（テナント数・端末総数・横断の非準拠/同期遅延・未割当件数・バインド未完了テナント）。
- **未割当（退避キュー）**（`/unassigned`）: テナントを一意に特定できなかった通知・端末（NFR 2.3）の可視化と再割当。
- **横断監査ログ**（`/audit`）: 全テナントの監査ログを横断追跡（テナント列・テナント絞り込み）。

## 9. UI スコープ外（デザインしない）

requirements.md の Out of Scope に対応。**これらの UI は作らない**:
- zero-touch / Knox / NFC のエンロール画面（QR のみ）
- Work Profile(BYOD) / COPE の個人領域 UI
- Lost Mode / eSIM 管理 / 直接 APK 配信 / RESET_PASSWORD・RELINQUISH_OWNERSHIP・CLEAR_APP_DATA
- 高度な compliance 自動 enforcement の設定 UI
- 限定公開/プライベートアプリの開発フロー、Web アプリ(PWA) 配信
- USAGE_LOGS の収集・分析画面

## 10. 非交渉の制約（デザイン時に必ず守る）

1. **他テナントのデータは一切出さない**（存在も示唆しない）。一般ロールは自テナント固定。
2. **Managed Google Play の iframe 内部は再デザインしない**（Google 提供 UI）。枠と周辺だけを設計。
3. **WIPE / テナント削除は二段階確認**（§4.5）。誤操作を構造的に防ぐ。
4. **コマンドは非同期**（§4.4）。即時完了として描かない。
5. **ロール可視性（§5）を全画面で反映**。disabled+理由 か 非表示 を §4.2 の規則で。
6. **対象は Android 10+**。未満は `サポート対象外` として扱う。
7. ライト/ダーク両対応・日本語 UI・データ密 admin 密度（§2）。
